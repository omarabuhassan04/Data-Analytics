# نظام اللوازم — مجموعة السنابل الكشفية

نظام إدارة اللوازم والعهد والمشتريات لمجموعة كشفية من ثلاث فرق. الواجهة عربية
بالكامل ومن اليمين إلى اليسار، ونموذج الصلاحيات مفروض على الخادم لا في المتصفّح.

---

## التشغيل محلياً

```bash
npm install
```

قاعدة بيانات PostgreSQL محلية تُدار من داخل المشروع (ثنائيات رسمية، بلا تثبيت
على النظام). شغّلها في طرفية مستقلة واتركها تعمل:

```bash
npm run dev:db
```

ثم في طرفية أخرى:

```bash
npm run db:push
```

```bash
npm run db:seed
```

```bash
npm run dev
```

افتح <http://localhost:3000>.

## المسارات الثلاثة

### ١) طلب لوازم — للمتوفّر في المقر

يُعتمد **آلياً** بلا خطوة موافقة. الكميات تُخصم من المخزون في نفس المعاملة التي
تُنشئ الطلب، فتبقى «الكمية المتاحة» التي تراها بقيّة الفرق صادقة. ما صُرف يصبح
**عهدة** على الفرقة حتى يُرجَع ويُعتمد.

الحالات: `تم الصرف — عهدة قائمة` ← `بانتظار التحقق` ← `مكتمل`.

### ٢) طلب شراء — لغير المتوفّر

مسار منفصل تماماً. يبدأ `قيد الانتظار` ولا يمسّ المخزون. قائد اللوازم يوافق أو
يرفض **مع ذكر السبب إلزامياً**. المرفوض تعدّله الفرقة وتعيد تقديمه فيعود
`قيد الانتظار` ويرتفع رقم المراجعة. المعتمد يظهر عندها للأدوار الرقابية.

**المخزون لا يتغيّر بالموافقة** — بل عند تسجيل التوريد بعد وصول البضاعة فعلاً،
وهناك يُنشأ الصنف أو تُضاف الكمية إلى صنف قائم.

الحالات: `قيد الانتظار` · `تمت الموافقة` · `مرفوض` · `تم التوريد` · `ملغى`.

### ٣) إرجاع العهدة — بالتحقّق

الفرقة تصرّح بما تُرجعه (سليم / تالف / مفقود). التصريح **دعوى لا رصيد**: لا
يتغيّر المخزون به إطلاقاً. قائد اللوازم يعاين ويعتمد الكميات الفعلية — وهي
اللحظة الوحيدة التي يتحرّك فيها المخزون:

| ما اعتُمد | الأثر على المتاح | لماذا                                         |
| --------- | ---------------- | --------------------------------------------- |
| سليم      | يعود للمخزون     | صالح للصرف من جديد                            |
| تالف      | لا يعود          | خرج عند الصرف، ويُسجَّل في عدّاد التالف       |
| مفقود     | لا يعود          | خرج عند الصرف، ويُسجَّل في عدّاد المفقود      |

مثال: صُرفت ١٠ خيام، أُرجع ٨ سليم و١ تالف و١ مفقود ← يعود **٨ فقط** إلى المتاح،
ويُسجَّل ١ تالف و١ مفقود خارجه. الإرجاع الجزئي مدعوم: تبقى العهدة مفتوحة بالباقي.

المتبقّي في العهدة ليس حقلاً مخزَّناً بل يُشتقّ دائماً:

```
المتبقّي = المصروف − السليم − التالف − المفقود
```

المعادلة في `outstanding()` داخل [`domain.ts`](src/lib/domain.ts)، ويستوردها
الخادم والمتصفّح معاً فلا يمكن لرقم معروض أن يخالف ما يفرضه الخادم.

## سلامة البيانات

**دفتر الحركة هو المصدر.** كل تغيّر في رصيد أي صنف يمرّ حصراً عبر
`applyMovement()` في [`stock.ts`](src/lib/stock.ts) — لا يوجد في المشروع أي
`item.update` يمسّ الكميات خارج هذا الملف، بما في ذلك الجرد وإضافة الأصناف.
لذلك المطابقة صحيحة بحكم البناء لا بحكم العادة:

```
مجموع حركات الصنف = رصيده المخزّن
```

صفحة **دفتر الحركة** تعرض هذا الإثبات لكل صنف، و**تُبلّغ** عن أي انحراف بدل
تصحيحه صامتاً — التصحيح التلقائي يخفي العلّة التي سبّبته.

ضمانات أخرى:

- **الخصم ذرّي**: `updateMany where quantity >= n` بدل قراءة ثم كتابة، فطلبان
  متزامنان لا يصرفان القطعة نفسها مرّتين، ولا يهبط رصيد تحت الصفر.
- **كل عملية داخل معاملة** مع سطر سجلّها، فإمّا أن يُحفظ التغيير وأثره معاً أو
  لا يُحفظ أيّهما.
- **الأرقام المرجعية مشتقّة من معرّف السجل** لا من عدد السجلات، فلا يتولّد رقم
  مكرّر عند التقديم المتزامن.
- **لا حذف**: الأصناف تُؤرشف، والحسابات تُعطَّل — حتى لا تنقطع مراجع السجلات.

## الصلاحيات

المصفوفة في [`domain.ts`](src/lib/domain.ts) وهي المرجع الوحيد. كل إجراء على
الخادم يبدأ بـ `requirePermission(...)`، وكل صفحة بـ `requirePage(...)`. إخفاء
الأزرار في الواجهة تحسين لتجربة الاستخدام فقط وليس حدّاً أمنياً: قائد فرقة يعرف
رابط `/manage/items` يصل إلى صفحة «لا تملك صلاحية»، ولو نادى الإجراء مباشرة
لرُفض على الخادم.

قائد الفرقة مقيَّد بفرقته في كل استعلام عبر `teamFilter()` في
[`scope.ts`](src/lib/scope.ts) — القيد يُبنى في مكان واحد حتى لا تنساه صفحة جديدة.

| الصلاحية            | قائد اللوازم | قائد فرقة | الأدوار الرقابية |
| ------------------- | :----------: | :-------: | :--------------: |
| قراءة المخزون       |      ✅      |    ✅     |        ✅        |
| إدارة المخزون والجرد |      ✅      |     —     |        —         |
| تقديم طلب لوازم     |      —       |    ✅     |        —         |
| تقديم طلب شراء      |      —       |    ✅     |        —         |
| البتّ في طلبات الشراء |      ✅      |     —     |        —         |
| التوريد للمخزون     |      ✅      |     —     |        —         |
| تقديم إرجاع         |      —       |    ✅     |        —         |
| اعتماد الإرجاع      |      ✅      |     —     |        —         |
| إدارة الحسابات      |      ✅      |     —     |        —         |
| سجل كل الفرق        |      ✅      |     —     |        ✅        |

الأدوار الرقابية لا ترى طلب شراء **قبل** البتّ فيه — الطلب قيد الدراسة شأن
الفرقة وقائد اللوازم.

## البنية

- **Next.js 15 (App Router) · React 19 · TypeScript · Tailwind CSS v4**
- **PostgreSQL + Prisma 6** — القراءات في مكوّنات الخادم، والكتابات في
  Server Actions يبدأ كلٌّ منها بحارس صلاحية.
- **الجلسة**: JWT موقّع (HS256, `jose`) في كعكة `httpOnly`، ومدّتها ١٢ ساعة.
  المستخدم يُعاد تحميله من قاعدة البيانات مع كل طلب، فتعطيل حساب يسري فوراً.
- **كلمات المرور**: `bcrypt`.
- **التحقّق**: `zod` على كل مدخل، ورسائل الخطأ عربية جاهزة للعرض.

| الملف                                                      | الغرض                                |
| ---------------------------------------------------------- | ------------------------------------ |
| [`src/lib/domain.ts`](src/lib/domain.ts)                   | الأدوار والصلاحيات والحالات ومعادلة العهدة |
| [`src/lib/stock.ts`](src/lib/stock.ts)                     | بدائية حركة المخزون والمطابقة        |
| [`src/lib/guard.ts`](src/lib/guard.ts)                     | حراس الصفحات                          |
