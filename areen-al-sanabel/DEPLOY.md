# النشر العام — عرين السنابل

## لماذا لا يكفي الضغط على «نشر»

التطبيق يعمل حاليًا على **SQLite** بملف محلي (`prisma/dev.db`). منصّات الاستضافة
بلا خوادم (Vercel وأمثالها) تعطي نظام ملفات **للقراءة فقط**، ومحتواه يُمحى مع كل
تشغيل. وبما أن كل عملية دخول تكتب سطرًا في سجلّ النشاط، فإن النشر بالإعداد الحالي
ينتج موقعًا يفتح صفحة الدخول ثم يفشل عند أول ضغطة.

لذلك يحتاج النشر العام إلى **قاعدة PostgreSQL**. المخطّط جاهز لها منذ البداية،
والتحويل سطر واحد.

## قبل النشر — ثلاث مسائل أمنية إلزامية

| المسألة | الوضع الحالي | المطلوب |
| --- | --- | --- |
| كلمات المرور | الحسابات السبعة كلها بكلمة `Areen@2026` وهي مذكورة في التوثيق | كلمة مرور قوية لكل حساب |
| `AUTH_SECRET` | قيمة تطوير افتراضية معروفة — من يعرفها يزوّر جلسة أي مستخدم | قيمة عشوائية جديدة |
| لوحة الحسابات التجريبية | تظهر في صفحة الدخول خارج بيئة الإنتاج | تختفي تلقائيًا عند `NODE_ENV=production` |

الشيفرة تفرض أول اثنتين: التطبيق **يرفض الإقلاع** في الإنتاج بالمفتاح الافتراضي،
وملف البذور **يرفض العمل** بكلمة المرور الافتراضية.

## الخطوات

```bash
npm run deploy:prep
```

يحوّل المخطّط إلى PostgreSQL، ويولّد `AUTH_SECRET` جديدًا في `.env.production.local`
(مستثنى من Git، ولا يُطبع على الشاشة).

ثم املأ في ذلك الملف:

- `DATABASE_URL` — سلسلة اتصال PostgreSQL من مزوّد الاستضافة
- `SEED_DEFAULT_PASSWORD` — كلمة مرور قوية للحسابات الأولى

انسخ المتغيّرات الثلاثة إلى إعدادات البيئة عند المزوّد، ثم أنشئ الجداول:

```bash
npx prisma db push
```

```bash
npx prisma db seed
```

> **لماذا `db push` وليس `migrate deploy`؟**
> ملفات الهجرة الموجودة في `prisma/migrations` وُلّدت لـ SQLite، وتحتوي على صياغة
> خاصّة به (`AUTOINCREMENT`, `DATETIME`) يرفضها PostgreSQL. الأمر `db push` يبني
> الجداول من `schema.prisma` مباشرةً فيتجاوز المشكلة.
>
> إن أردت سجلّ هجرات حقيقيًّا لـ Postgres لاحقًا: احذف مجلّد `prisma/migrations`
> بعد التحويل، ثم شغّل `npx prisma migrate dev --name init` وأنت متّصل بقاعدة
> Postgres، وستُولَّد هجرة أولى بصياغة صحيحة.

وبعد أول دخول، غيّر كلمات مرور جميع الحسابات من `/manage/users`.

للعودة إلى التطوير المحلي:

```bash
npm run deploy:prep -- --revert
```

## مزوّدو PostgreSQL المناسبون

أي مزوّد يعطي سلسلة اتصال يكفي — Neon أو Supabase أو Vercel Postgres أو خادم
داخلي في المقرّ. المخطّط قياسي بلا امتدادات خاصة.

## ملاحظة على «رابط عام»

هذا النظام أداة داخلية خلف تسجيل دخول: الرابط يكون عامًّا بمعنى أنه يُفتح من أي
مكان، لكن المحتوى يبقى محجوبًا خلف الحسابات. لا يُنصح بإتاحة المخزون والطلبات
لغير المنتسبين للمجموعة.

لا توجد في النظام صفحة عامة بلا حساب: كل المسارات خلف الدخول ما عدا `/login`.
